## 🏗 Архитектура безопасности v1.0.1

Seednox v1.0.1 — это **локальное ПК-приложение** + **Telegram-бот** для хранения секретов. Архитектура построена по принципу «нулевого доверия к серверу»: все чувствительные данные шифруются **до** записи в базу данных.

### Схема потока данных

```
Пользователь → вводит секрет в Telegram-бот
                        ↓
          Мастер-пароль (RAM) + Соль пользователя
                        ↓
              Argon2id KDF (t=3, m=64MB, p=4)
                        ↓
              AES-256-GCM ключ (256-бит, в RAM)
                        ↓
          Зашифрованный blob → SQLite (seednox.db)
                        ↓
          Только зашифрованный текст хранится на диске
```

### Что мы НЕ храним нигде

- Секреты (сид-фразы, пароли, приватные ключи, заметки) в открытом виде.
- Мастер-пароль в базе данных или логах.
- Ключи шифрования на диске — существуют только в RAM пока сейф открыт.
- Какие-либо данные пользователей на внешних серверах (self-hosted архитектура).

### Что хранится в базе данных (всё зашифровано)

| Данные | Криптография | Примечание |
|--------|-------------|------------|
| **Содержимое записи** | `AES-256-GCM` | 12-byte random nonce + ciphertext + 16-byte GCM auth tag |
| **Заметка к записи** | `AES-256-GCM` | Тот же ключ, независимый nonce |
| **Тип записи** (`entry_type`) | Открытый текст | Хранится только тип (seed/password/etc.), не содержимое |
| **Хэш пароля** | `Argon2id` | Только для проверки пароля, восстановить невозможно |
| **Соль пользователя** | `os.urandom(32)` | 32 байта, уникальна для каждого пользователя |
| **Портативный бэкап** | `AES-256-GCM` + заголовок `SNX1` | Embedded salt, полностью самодостаточный файл |

## 🔐 Детали криптографии

### Argon2id — защита мастер-пароля

```
Параметры: t=3 (время), m=65536 KB (64 МБ RAM), p=4 (потоки)
Соль: os.urandom(32) — уникальна для каждого пользователя
Результат: 32-байтовый ключ для AES-256-GCM
```

Параметры выбраны по рекомендации OWASP 2024 как минимально приемлемые для хранения паролей. Перебор невозможен без значительных ресурсов.

### AES-256-GCM — шифрование записей

```
Ключ: 256-бит (производный от Argon2id)
Nonce: os.urandom(12) — уникальный для каждой операции записи
Режим: GCM (Galois/Counter Mode) — аутентифицированное шифрование
Tag: 16 байт — защита целостности (AEAD)
```

Использование GCM означает, что **подделка или повреждение зашифрованных данных будет обнаружена** при расшифровке.

## 🛡 Защита от угроз

| Угроза | Мера защиты | Детали |
|--------|-------------|--------|
| **Брутфорс мастер-пароля** | Argon2id KDF | 64 МБ RAM на попытку делает массовый перебор нецелесообразным |
| **Онлайн-перебор** | Rate limiting | Блокировка после 5 неверных попыток на 15 мин |
| **Кража базы данных** | AES-256-GCM | Без мастер-пароля расшифровка невозможна |
| **Перехват сессии** | Авто-таймаут | Сейф блокируется после 15 мин неактивности |
| **Несанкционированный доступ** | `ALLOWED_USER_IDS` | `AccessControlMiddleware` отбрасывает чужие Telegram-запросы |
| **Утечки через чат** | Авто-удаление | Сообщения с секретами удаляются сразу после обработки |
| **Утечки через логи** | Фильтрация | Чувствительные данные никогда не попадают в логгер |
| **SQL-инъекции** | Параметризация | Все запросы через `aiosqlite` с параметрами |
| **Подделка бэкапа** | GCM Auth Tag | Изменённый файл `.snx` не откроется |
| **Блокировки Telegram API** | SOCKS5/HTTP прокси | Встроенная поддержка зеркал API и прокси |

## 📋 Рекомендации пользователям

1. **Сильный мастер-пароль** — минимум 12 символов, буквы + цифры + спецсимволы. Оценка силы показывается в реальном времени при создании.
2. **Блокируйте сейф** после каждого использования (`🔒 Заблокировать`).
3. **Self-host** — для максимальной безопасности запускайте бота на своём сервере (рекомендуем **@ohoster** для VPS).
4. **Регулярные бэкапы** — экспортируйте `.snx` файлы и храните в надёжном зашифрованном месте.
5. **Проверяйте код** — проект полностью open-source именно для этого.
6. **Не пересылайте секреты** в другие чаты, даже зашифрованными.

## ⚠️ Известные ограничения

- Seednox — **хранилище**, не кошелёк. Транзакции не подписываются, средства не хранятся.
- Telegram-боты не используют end-to-end шифрование. Использование self-hosted бота значительно снижает риски.
- **Потеря мастер-пароля = безвозвратная потеря доступа** ко всем записям. Никакого восстановления нет и быть не может — это особенность дизайна.
- Файл `seednox.db` зашифрован на уровне содержимого, но **не** на уровне файловой системы. Рекомендуется использовать шифрование диска (BitLocker, VeraCrypt).
