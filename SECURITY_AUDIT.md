# Аудит безопасности Seednox

> Независимый обзор безопасности исходного кода приложения **Seednox** — локального
> зашифрованного хранилища seed-фраз (десктоп-сейф + опциональный Telegram-бот).

| | |
|---|---|
| **Объект** | `github.com/novirx-tg/seednox` |
| **Версия / коммит** | v1.0.1 · `70ab3e6` |
| **Тип** | Ревью исходного кода (whitebox), без формальной сертификации |
| **Метод** | Ручной разбор криптографии, управления ключами, контроля доступа, хранения, работы с памятью |
| **Режимы** | (A) Локальный сейф в десктоп-GUI · (B) Опциональный Telegram-бот (self-host) |

> ⚠️ Это независимый обзор кода, а **не** формальный платный аудит и не гарантия
> отсутствия уязвимостей. Он не заменяет профессиональный аудит с ответственностью
> исполнителя. Храните основные ключи от крупных сумм на аппаратном кошельке.

---

## 1. Итог

Криптографическое ядро **реализовано грамотно**: аутентифицированное шифрование
(AES-256-GCM), стойкая функция вывода ключа (Argon2id), корректные соли,
разделение хеша для верификации пароля и ключа шифрования. Фатальных
криптографических дефектов не обнаружено.

Основные риски лежали **не в самой крипте, а в операционной части**: метаданные
хранились открытым текстом, отсутствовала автоблокировка по простою, буфер обмена
не очищался, секреты не затирались в памяти. Все четыре пункта закрыты в этом
изменении (см. §4).

**Общая оценка:** для локального офлайн-режима — надёжный «сейф» уровня хорошего
локального менеджера паролей. Безопасность теперь определяется преимущественно
чистотой компьютера пользователя.

## 2. Модель угроз

| Актив | От кого защищаем |
|---|---|
| Seed-фразы, приватные ключи, пароли, заметки | Кража файла БД; вредонос на ПК; подглядывание; принуждение |
| Мастер-пароль | Брутфорс; извлечение из памяти/дампа |
| Метаданные (названия, история действий) | Утечка при краже файла БД |

**Вне модели угроз:** заражённый вредоносом ПК (кейлоггер/инфостилер видит всё —
как и у любого софтового менеджера паролей); скомпрометированный аппаратно ПК;
атаки на сам Telegram (актуально только для режима B).

### Что сделано хорошо (подтверждено ревью)

- **AES-256-GCM** — аутентифицированное шифрование, случайный 12-байтный nonce на операцию.
- **Argon2id** (t=3, m=64 МБ, p=4) → HKDF-SHA256 для вывода ключа; параметры на уровне/выше рекомендаций OWASP.
- **Соль** 32 байта из ОС-CSPRNG, уникальная на пользователя.
- Хеш пароля для верификации **отделён** от ключа шифрования.
- Мастер-пароль не пишется на диск; лимит попыток + блокировка; duress/decoy-режим.

## 4. Реализованные исправления (этот changeset)

### 4.1 Автоблокировка сейфа по простою (F-2)

GUI отслеживает активность пользователя (клавиатура/мышь) и по истечении
`SESSION_TIMEOUT` секунд простоя автоматически вызывает блокировку: сейф
закрывается, буфер очищается, мастер-пароль и ключ метаданных **затираются** в
памяти. Реализация: `src/gui/app.py` (`_start_idle_watch`, `_check_idle`,
`_vault_lock`).

### 4.2 Автоочистка буфера обмена (F-3)

После копирования seed запускается таймер (по умолчанию 40 с), по которому буфер
очищается — **но только если там всё ещё лежит наш секрет** (чтобы не затереть то,
что пользователь скопировал позже). Буфер также очищается при блокировке и закрытии
приложения. Реализация: `_copy_to_clipboard`, `_do_clear_clipboard`,
`_flush_clipboard_now`.

> Рекомендация пользователю: отключите облачную синхронизацию буфера обмена
> (Windows: *Буфер обмена → Синхронизация между устройствами*), иначе секрет может
> уйти на другие устройства до автоочистки.

### 4.3 Шифрование названий и аудит-лога (F-1)

Новый модуль `src/security/metadata.py` — `MetaCipher`: шифрует названия записей и
детали аудита той же схемой (AES-256-GCM), но **ключ выводится один раз** на сессию
(Argon2id слишком дорог, чтобы вызывать его на каждое имя в списке).

- Формат хранения: `snxm1:` + base64(nonce‖ciphertext). Старые (открытые) значения
  без префикса распознаются и возвращаются как есть → полная обратная совместимость.
- **Ленивая миграция:** при разблокировке ранее открытые названия и детали аудита
  автоматически перешифровываются (`repository.encrypt_legacy_names` /
  `encrypt_legacy_audit`), по одной таблице за раз, чтобы не смешивать ключи
  реального и duress-режима.
- Поиск и проверка уникальности имён перенесены в код (после расшифровки), так как
  на шифртексте SQL `LIKE`/`UNIQUE` не работают.

### 4.4 Затирание секретов в памяти (F-4)

Новый модуль `src/security/memory.py` (`wipe`, `SecretBytes`). Мастер-пароль в GUI
теперь хранится как `bytearray` и **зануляется** при блокировке/закрытии; ключ
`MetaCipher` также затирается. Крипто-функции (`derive_key`, `hash_password`,
`verify_password`, `encrypt_seed`, `decrypt_seed`) принимают `str | bytes |
bytearray`.

> Ограничение Python: обычные `str` (введённый пароль, расшифрованная seed на экране)
> неизменяемы и не могут быть надёжно затёрты. Затирание применяется к тому, что
> реально можно — к долгоживущему ключу и паролю сессии. Полная защита памяти
> требует нативного кода/ОС-механизмов и вне возможностей чистого Python.

### Тесты

Добавлен headless-тест `tests/test_metadata_security.py` (без GUI/Telegram):
round-trip шифрования с паролем-`bytearray`, MetaCipher + обратная совместимость,
ленивая миграция названий/аудита (идемпотентность), поиск и уникальность.
Запуск: `python tests/test_metadata_security.py`.

## 5. Остаётся сделать (рекомендации)

1. **F-5 — шифрование файла БД по умолчанию.** Включать SQLCipher (`DB_ENCRYPTION_KEY`)
   и предусмотреть его для десктоп-режима, а не только Linux/Docker. Сейчас на Windows
   файл БД не шифруется (секреты внутри — под AES, но это дополнительный слой).
2. **F-7 — fail-closed доступ бота.** Сделать `ALLOWED_USER_IDS` обязательным при
   запуске бота (сейчас пустое значение = бот открыт всем).
3. **F-6 — режим Telegram-бота.** Помнить, что сообщения ботов не E2E: seed проходит
   через серверы Telegram. Для критичных ключей использовать только локальный режим.
   *(Разработчик закрыл публичного бота именно ради этой гарантии — верное решение.)*
4. **F-8 — подпись и воспроизводимость сборки.** Публиковать контрольные суммы и
   подпись Windows-бинарника; поощрять запуск из исходников.
5. **Handlers бота ещё не подключены к шифрованию метаданных.** После этого изменения
   названия хранятся зашифрованными, поэтому перед повторным включением бота нужно
   провести ту же интеграцию `MetaCipher` в `src/bot/keyboards.py`, `handlers/wallets.py`,
   `handlers/reauth.py`, `handlers/settings.py`, `handlers/unlock.py`. Пока бот отключён —
   не блокирует локальный режим.
6. **F-9 — внешний аудит.** Заказать независимый аудит криптографии перед
   позиционированием как хранилища для крупных сумм; расширить тестовое покрытие.

---

## 6. Рекомендации пользователю

- Используйте **локальный офлайн-режим** на чистом, доверенном ПК.
- Мастер-пароль — длинная уникальная фраза (20+ символов).
- Включите SQLCipher, если запускаете вне Windows-GUI.
- Отключите облачную синхронизацию буфера обмена.
- Не храните здесь seed от «холодных» кошельков с крупными суммами — для них
  аппаратный кошелёк + офлайн (металлический) бэкап.
